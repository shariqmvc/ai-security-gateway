# 7.6.1 Platform/Tenant Authorization Boundary Fix

## Problem reproduced

A platform API key calling a tenant-scoped endpoint such as:

`GET /api/cost/tenant/{tenantId}`

previously reached `TenantAccessGuard`, which called `TenantContext.require()` directly. Platform principals intentionally have no tenant context, so the request became an `IllegalStateException` and was returned as HTTP 500.

## Correct contract

- Missing/invalid API key -> **401 Unauthorized**
- Tenant principal -> own tenant-scoped resource -> **200 OK** when role permits
- Tenant principal -> another tenant -> **403 Forbidden**
- Platform principal -> tenant-scoped business data -> **403 Forbidden**
- Platform principal -> `/admin/**` control-plane API -> allowed when the platform role permits it
- Tenant principal -> `/admin/**` -> **403 Forbidden**

## Implementation

`TenantAccessGuard` now delegates authorization to `AuthorizationService.requireTenantRole(...)` instead of directly requiring `TenantContext`. This makes the platform-vs-tenant distinction explicit and prevents platform requests from falling through to a missing tenant context.

`TenantAccessDeniedException` now produces an explicit platform-principal message when no authenticated tenant exists, and `GlobalExceptionHandler` returns that message as HTTP 403.

## Postman validation

### 1. Platform admin API

```http
POST {{baseUrl}}/admin/tenants
X-API-Key: {{platformApiKey}}
```

Expected: normal admin behavior (for example 201 for a new tenant or 409 for a duplicate tenant).

### 2. Tenant cannot use admin API

```http
POST {{baseUrl}}/admin/tenants
X-API-Key: {{tenantOwnerApiKey}}
```

Expected: **403 Forbidden**.

### 3. Tenant can access its own cost

```http
GET {{baseUrl}}/api/cost/tenant/{{tenantId}}
X-API-Key: {{tenantOwnerApiKey}}
```

Expected: **200 OK** when the tenant role permits cost access.

### 4. Tenant cannot access another tenant's cost

```http
GET {{baseUrl}}/api/cost/tenant/{{otherTenantId}}
X-API-Key: {{tenantOwnerApiKey}}
```

Expected: **403 Forbidden**.

### 5. Platform key cannot access tenant cost

```http
GET {{baseUrl}}/api/cost/tenant/{{tenantId}}
X-API-Key: {{platformApiKey}}
```

Expected: **403 Forbidden**, not 500.

Expected response shape:

```json
{
  "status": 403,
  "error": "Forbidden",
  "message": "The authenticated principal is not authorized to access tenant-scoped data."
}
```

### 6. Correct entitlement quota URL

The implemented endpoint is:

```http
GET {{baseUrl}}/admin/entitlements/tenants/{{tenantId}}/quota
X-API-Key: {{platformApiKey}}
```

The shorter `/admin/entitlements/{{tenantId}}/quota` path is not mapped and should not be used unless an explicit compatibility alias is added.
