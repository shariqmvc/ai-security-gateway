# P11.9.2 — Semantic Retrieval

## Status

Offline semantic retrieval implementation.

## Data flow

```text
semantic_security_v1/train.jsonl
        |
        v
nomic-embed-text
        |
        v
768-d vector
        |
        v
PostgreSQL + PGVector
        |
        v
cosine nearest-neighbor search
```

The validation set can be indexed for development experiments.

The independent `test.jsonl` is intentionally NOT indexed.

## Why test is excluded

If test examples are inserted into the reference vector database, the
retrieval benchmark becomes contaminated: the query can retrieve itself or
a near-duplicate from the benchmark.

The test set is therefore used only as query input during evaluation.

## Search metric

PGVector uses cosine distance:

```sql
embedding <=> query_embedding
```

The SQL function converts this to similarity:

```text
similarity = 1 - cosine_distance
```

## Current scope

P11.9.2 is an offline semantic retrieval benchmark.

It does NOT:
- block requests
- modify GatewayService
- modify PersonalFirewallClient
- modify PersonalSecurityIntelligenceService
- change P11.8 behavior
- make production security decisions

## Recommended sequence

1. Check Ollama and PGVector environment.
2. Apply SQL schema.
3. Index train corpus.
4. Optionally index validation corpus only if explicitly desired for development.
5. Run manual semantic queries.
6. Run independent test evaluation.
7. Review top-K retrieval quality and latency.
8. Only then design the combined policy layer.
